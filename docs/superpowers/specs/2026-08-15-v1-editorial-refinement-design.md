# 深大志联宣传部 PR v1 编辑部式精修改版规格

## 1. 改版目标

在不更换深大志联宣传部 PR 现有品牌气质、不改变单页信息架构、不替换真实团队素材的前提下，对 v1 招新网页进行一次保留式精修。

本次重点解决四个问题：最小字号过小、首屏在桌面端和手机端过长、区块标题与卡片布局重复、页面视觉层级依赖过多英文编号眉题。成品仍应保留奶油白、珊瑚粉、酒红、宋体标题和真实照片拼贴所形成的柔软编辑部气质，但整体更清楚、更轻松、更适合手机阅读。

设计参数固定为：

- `DESIGN_VARIANCE: 6`：采用克制的不对称布局，不追求实验性错位。
- `MOTION_INTENSITY: 4`：保留有目的的入场、显现和反馈动画。
- `VISUAL_DENSITY: 4`：信息完整，但用留白和不同布局节奏减少拥挤。

## 2. 改版模式与边界

本项目属于“Redesign - Preserve”。现有品牌、信息架构、锚点、导航标签、真实照片、二维码、组织归属和内容事实均为保留项。

本次允许：

- 调整字体角色、字号、字重、行距、字距和段落宽度。
- 重新组合首屏、三个分组、加入收获、真实日常、FAQ 和二维码区的版式。
- 在不改变事实的前提下压缩重复文案或改写过长辅助说明。
- 删除编号式英文眉题、重复状态信息和纯装饰性小字。
- 增加自动深色模式、图片加载降级和更明确的交互状态。
- 生成并使用一张不含人物、文字、标志的低对比纸张纹理，只作为辅助背景。

本次不允许：

- 修改 URL、现有区块锚点或主要导航标签。
- 修改品牌名称、PR 标识、组织归属、招新群名称、二维码内容或有效期事实。
- AI 重绘、换脸或修改任何真实成员照片。
- 虚构招新人数、筛选条件、活动成果、奖项、培训承诺或联系方式。
- 引入新的后端、表单、账号系统、数据库或第三方运行时服务。
- 修改 v2、v3、当前版本或仓库中与 v1 无关的文件。

## 3. 视觉系统

### 3.1 颜色

玫红继续作为全页唯一强调色。奶油白和柔粉构成浅色模式的页面与次级表面，深酒红用于主要文字和高对比行动区域。现有浅蓝、淡黄不再作为独立强调色使用，避免同页出现多个竞争色。

浅色模式的色彩职责：

- 页面背景：奶油白。
- 次级表面：柔粉或接近背景的淡玫瑰色。
- 主要文字：深酒红。
- 次要文字：通过对比度检查的暖灰紫。
- 唯一强调色：珊瑚玫红。
- 反白文字：带轻微暖色的近白色，不使用纯白。

深色模式通过 `prefers-color-scheme: dark` 自动启用。全页切换为深酒红和近黑酒红表面，文字使用暖白，强调色仍为同一玫红。深色模式不在单个区块内随机翻转；浅色与深色都保持同一信息层级。

### 3.2 字体角色

字体不要求全站统一为一种，但必须按照内容角色稳定使用，最多保留三套字体角色：

1. 中文展示字体：`Songti SC`、`STSong`、`Noto Serif CJK SC` 与通用 serif 回退。仅用于首屏标题、区块标题和少量三级标题，保留编辑部气质。
2. 中文正文与界面字体：`PingFang SC`、`Microsoft YaHei`、系统 sans-serif 回退。用于正文、导航、按钮、FAQ、说明和二维码文字，优先保证清晰度。
3. 英文短标签字体：`Avenir Next`、`SF Pro Display`、`Helvetica Neue` 与系统 sans-serif 回退。仅用于极少量短英文品牌信息，不用于长段正文，也不使用等宽字体制造技术感。

禁止在同一标题中随意混入另一套字体强调单个词。标题强调仅通过同一字体的字重或颜色完成。

字号下限与层级：

- 全站任何可见文字不得低于 12px。
- 图片说明、英文短标签、日期和辅助状态为 12-13px。
- 次要说明和页脚文字为 14px。
- 导航、按钮和卡片辅助正文为 15px 或更大。
- 正文为 16-17px，行高约 1.7-1.85，段落宽度不超过约 65 个拉丁字符的视觉宽度。
- 卡片标题为 26-34px。
- 区块标题为 40-60px，根据视口收缩。
- 首屏标题桌面端约 56-64px，手机端约 34-42px，以保持自然换行和首屏完整为准。

### 3.3 形状与材质

形状规则固定为：内容卡片与图片使用 16px 圆角，按钮使用胶囊圆角，品牌圆形标识维持圆形，二维码图片本身不裁切、不加遮挡圆角。

阴影只用于首屏主照片和二维码行动容器，并使用与背景同色相的柔和阴影。普通内容优先通过留白、色块和单侧分隔建立层级，不把所有内容装进悬浮卡片。

生成的纸张纹理必须低对比、无可读文字、无人物、无标志，只在首屏或页面固定背景中以低不透明度使用。纹理关闭或加载失败时，纯色背景仍应完整可用。

## 4. 页面结构与布局

### 4.1 顶部导航

桌面导航高度控制在 68-72px，所有内容单行显示。品牌标识、既有导航标签和“加入招新群”行动入口保持清楚。相同加入意图在导航、首屏和页尾统一使用“加入招新群”标签，不再同时出现“立即加入”“加入我们”等近义标签。

手机端保留品牌和主行动按钮，导航高度约 64-68px。按钮文字必须单行显示，点击区域不小于 44px。

### 4.2 首屏

首屏采用非对称图文分栏。桌面端左侧为信息，右侧为真实主照片和一张小型辅助照片；手机端改为严格单列，主照片位于行动区下方并使用更短的固定视觉高度。

首屏最多包含四类文字元素：

1. 一个具有真实语义的招募状态提示。
2. 主标题。
3. 一段压缩后的简介。
4. 一个主要按钮和一个次要文字入口组成的行动组。

桌面端标题固定为最多两行。首屏从导航下缘至区块结尾应适配常见 900px 高度，主要行动无需滚动即可看到。手机端以 390×844 为主要基线，状态、标题、简介、行动组和部分真实主照片应在初始视口内出现。

首屏移除重复季节胶囊、编号式英文眉题、纯装饰英文照片说明和版本式信息。主照片继续使用真实团队合照，辅助照片继续使用现有真实活动素材。

### 4.3 工作方向概览

原四格粉色横条改为更轻量的三项工作方向导航，只保留摄影、平面设计、公众号三个真实方向。它作为首屏与分组区之间的内容桥梁，不做无限滚动，也不增加装饰性口号。

### 4.4 三个分组

桌面端采用一个主模块加两个辅助模块的非对称三格布局，格子数量严格等于三个分组。主模块占据较大面积，两个辅助模块上下排列；视觉层级仅服务于构图，不改变三个分组的组织地位。

每个模块保留真实照片、分组名称、定位、工作内容和适合方向。编号圆点和覆盖在图片上的标签全部移除。图片下方直接进入文字内容，至少两个模块使用不同的背景层次或图片比例，避免三个等宽同构卡片。

小于 768px 时三个模块严格单列，顺序仍为摄影组、平面设计组、公众号组。

### 4.5 加入收获

四项收获改为 2×2 的排版组。每项用清楚标题、短说明和充足留白呈现，不使用长表格、进度条或每行上下双边框。该区块在浅色模式中仍属于浅色页面主题，不再整段翻转成独立深色网站。

手机端改为单列或紧凑的两列布局，具体由 360px 和 390px 下的可读性决定。任何正文不得因追求两列而低于 15px。

### 4.6 真实日常

继续使用五张现有真实照片，采用节奏更稳定的编辑式照片墙。桌面端混合横图、竖图和跨列图，手机端严格单列，避免小图并排导致人物主体过小。

每张图片下方使用标题和一行说明，不叠加图片标签，不使用装饰性摄影编号或虚构图片署名。图片区只承担真实作品和团队生活证明，不重复分组职责列表。

### 4.7 FAQ

FAQ 使用纵向标题、简短引导和折叠列表。标题与说明上下堆叠，不再使用重复的“左大标题、右小段落”区块头。每个问题的点击区域至少 52px 高，焦点状态清楚，展开内容保持 16px 正文。

在 JavaScript 不可用时，浏览器原生 `details` 与 `summary` 仍可操作。当前默认展开第一项的行为可以保留。

### 4.8 加入招新群

页尾使用一个包含式高对比行动面板，而不是整页主题翻转。面板中保留招新标题、群名称、扫码说明、二维码、有效期和更新提示。

二维码维持原始比例、白色静区和足够尺寸，不叠加纹理、滤镜、文字或装饰。桌面端文字与二维码并列，手机端文字在上、二维码在下。

当前二维码的页面文字为“8 月 19 日前有效”。如果验收或发布发生在 2026 年 8 月 19 日之后，必须停止把它表述为有效入口，并向用户索取更新二维码。

### 4.9 页脚

页脚保留 PR、组织归属、页面锚点和返回顶部入口。页脚文字不得低于 14px。链接标签沿用页面中的同一意图名称，不增加版本号、构建号、地点时间或装饰性状态信息。

## 5. 内容规则

- 保留“为什么加入、可以做什么、能得到什么、部门氛围、如何加入”的完整叙事。
- 不删除摄影组、平面设计组、公众号组的实际职责内容。
- 首屏简介可以压缩，但不得改变“用文字、镜头与设计让想法落地”的含义。
- 所有可见字符串在交付前逐一复读，修正语法不通、指代不清和刻意文艺的表达。
- 页面可见文本、图片说明、元数据和替代文本中不得出现长破折号或短破折号分隔符，日期范围使用普通连字符。
- 编号式英文眉题全部删除。全页最多使用两个主题型小标签，招募状态因具有真实状态语义不计为装饰眉题。
- 不出现虚构精确数字、滚动提示、版本标签、天气地点条、装饰状态点或重复行动标签。

## 6. 动效与交互

现有原生滚动显现控制器继续使用，不新增 Motion 或 GSAP 依赖。滚动显现从当前 38px、820ms 调整为约 20-24px、520-620ms，使内容更利落。

每个动画必须承担一种明确作用：

- 首屏入场：建立标题、行动和照片的阅读顺序。
- 区块显现：提示内容层级，不逐张卡片制造长延迟。
- 图片悬停：提示图片可被关注，但不暗示其可点击。
- 按钮按压：用轻微缩放或下移提供操作反馈。
- FAQ 展开：使用浏览器原生状态，不添加复杂高度动画。

所有动画只改变 `transform` 和 `opacity`。`prefers-reduced-motion: reduce` 下全部内容直接显示。不得添加原生滚动监听、滚动劫持、视差、无限跑马灯或自动循环动画。

## 7. 响应式与可访问性

响应式检查至少覆盖 1440×900、1024×768、768×1024、390×844 和 360×800。

- 所有大于一列的布局必须在小于 768px 时显式退化。
- 页面不得横向滚动。
- 导航桌面端单行，高度不超过 72px。
- 所有行动标签在桌面端和手机端均不得换行。
- 正文和按钮达到 WCAG AA 对比度，正文以 AAA 为目标。
- 焦点环在浅色和深色模式中均清楚可见。
- 图片保留准确 `alt`；纯装饰纹理使用空替代文本或 CSS 背景。
- 图片加载失败时保持稳定尺寸和替代文本，不造成明显布局位移。
- JavaScript 失效、滚动观察器失效或用户减少动态效果时，所有核心内容保持可见。

## 8. 工程实现范围

保留现有 Next.js、React、Tailwind v4、Vinext、Vite 和 Cloudflare 构建链，不新增第三方运行时依赖。

预计只修改或新增以下 v1 文件：

- `app/page.tsx`：重组语义结构和区块布局。
- `app/globals.css`：重建字体、颜色、间距、响应式、深色模式和动效样式。
- `app/recruitment-theme.ts`：压缩必要文案，移除编号式展示字段或调整内容标签。
- `app/layout.tsx`：同步清除元数据中的破折号分隔符并保持 SEO 含义。
- `tests/rendered-html.test.mjs`：补充内容结构、破折号、行动标签和必要预检断言。
- `public/assets/`：新增一张生成的无人物纸张纹理。
- 必要时新增只负责设计预检的测试文件，不改动业务或构建架构。

现有滚动显现控制器只在参数或标记映射确有需要时做最小修改。不得顺手重构数据库、worker、构建脚本或本地启动工具。

仓库当前存在与本任务无关的 archive 文件删除状态，实施和提交时必须保持不变，不得纳入本次提交。

## 9. 验收标准

### 9.1 内容与结构

- 现有五个主要锚点 `groups`、`benefits`、`stories`、`faq`、`join` 保持可用。
- 三个分组、四项收获、五条真实日常、三项 FAQ 和二维码信息完整出现。
- 所有加入意图统一使用“加入招新群”。
- 页面不存在长破折号、短破折号分隔符、编号式眉题或虚构内容。

### 9.2 字体与视觉

- 实际浏览器计算样式中，任何可见文字不低于 12px。
- 正文不低于 16px，特殊辅助文字不低于 12px。
- 中文标题、中文正文、英文短标签按照三类字体角色稳定使用。
- 全页仅使用玫红作为强调色，浅色和深色模式均通过对比度检查。
- 内容卡片和图片遵守 16px 圆角，按钮遵守胶囊圆角规则。
- 英文眉题数量不超过 `ceil(区块数 / 3)`，并优先做到零编号眉题。

### 9.3 首屏与响应式

- 桌面端首屏标题最多两行，行动区在初始视口内。
- 390×844 手机端初始视口可看到状态、标题、简介、行动组和部分主照片。
- 所有多列区块在手机端按本规格显式单列或可读地退化。
- 五个目标视口均无横向溢出、文字截断、按钮换行或图片主体严重误裁。

### 9.4 功能与动效

- 导航、首屏行动、FAQ、返回顶部和二维码显示保持可用。
- 滚动显现只播放一次，失败时内容可见。
- 减少动态效果模式下内容直接显示。
- 浏览器控制台无新增错误。

### 9.5 工程与视觉验收

- ESLint、构建、单元测试、渲染 HTML 测试和产物校验通过。
- 浅色和深色模式分别完成桌面端与手机端实际渲染检查。
- 逐一检查所有可见字符串、按钮、图片说明和替代文本。
- 实际测量字体下限、首屏高度、横向溢出、导航高度和 CTA 换行。
- 对照 `design-taste-frontend` 最终预检逐项记录结果，修复全部 P0、P1、P2 问题后再交付。
- 只提交本任务文件，不包含 archive 的既有删除或其他无关改动。

## 10. 完成定义

改版后的 v1 应当让熟悉原页面的人仍能立即认出深大志联宣传部 PR 的柔软编辑部气质，同时在常见手机上更容易阅读和行动。页面必须以真实素材和清楚信息为主，字体组合有变化但有规则，区块节奏有变化但不炫技，所有自动检查和实际浏览器验收均完成后才可视为交付。
