# v1 网页滚动浮现动画设计

## 背景

v1 招新网页目前只有首屏文字与图片在页面加载时执行一次 `rise` 动画。首屏以下的粉色横条、“三个分组”、“加入收获”、“真实日常”、FAQ、“加入我们”和页脚均为静态呈现。

本次改动为首屏以下内容增加滚动触发的由下向上浮现效果。视觉节奏采用已确认的“Apple 式平衡”，同时保持现有文案、图片、配色、布局、导航、悬停效果和交互功能不变。

## 目标

- 内容进入视口时，从下向上移动并淡入。
- 区块标题或介绍先出现，下方同组卡片或列表随后出现。
- 同一组中的多个卡片或列表项同时出现，不做逐项错峰。
- 每个内容单元在一次页面访问中只播放一次。
- 桌面、平板和手机端均生效。
- 尊重系统“减少动态效果”设置，并为缺少所需浏览器能力的情况提供可见内容降级。

## 非目标

- 不修改首屏现有的加载动画。
- 不增加视差、滚动绑定缩放、粘性叙事或滚动劫持。
- 不修改任何文案、图片、二维码、排版、色彩或响应式断点。
- 不引入 Framer Motion、GSAP 或其他动画依赖。
- 不改变卡片悬停、FAQ 展开、锚点导航、按钮和二维码行为。

## 已确认的视觉参数

- 位移距离：约 `38px`，方向为从下向上。
- 透明度：从 `0` 过渡到 `1`。
- 单次时长：约 `820ms`。
- 缓动：`cubic-bezier(0.22, 1, 0.36, 1)`，形成柔和减速。
- 标题与下方内容的层级延迟：约 `140ms`。
- 同组卡片或列表项：共享同一触发时刻和延迟，严格同时出现。
- 重复规则：观察到内容进入视口并触发后立即停止观察，不再次播放。

## 实现方案

采用原生 `IntersectionObserver` 与 CSS 状态类，不新增运行时依赖。

新增一个职责单一的客户端滚动观察器。页面保留现有服务端内容结构，只在需要参与动画的现有元素上增加 `data-reveal` 标记，并用可选的 CSS 自定义属性或数据属性表达约 `140ms` 延迟。同组内容只在其共同的外层容器上设置一个标记，例如 `group-grid`、`benefit-list`、`story-grid` 和 `faq-list`；不分别观察容器中的每张卡片或每个列表项，从结构上保证同组内容同时出现。观察器负责：

1. 获取所有带 `data-reveal` 的元素。
2. 检查“减少动态效果”偏好和 `IntersectionObserver` 支持情况。
3. 在支持动画时先建立观察，再在页面根节点添加 `reveal-ready` 状态；CSS 只在该状态存在时隐藏尚未出现的元素。
4. 元素进入触发区域后添加 `is-revealed` 状态并停止观察该元素。
5. 初始化失败时移除 `reveal-ready`，让所有内容恢复默认可见状态。
6. 组件卸载时断开观察器，避免残留监听。

CSS 负责初始状态和最终状态，只动画 `opacity` 与 `transform`。动画不会改写宽高、间距或定位，避免布局偏移，也不与卡片内部图片缩放和卡片悬停样式争用。

## 触发规则

- 建议使用约 `0.12` 的可见阈值，并将视口下边缘向上收约 `12%`，让动画在内容明显进入画面后开始。
- 标题与下方内容分别作为观察单元：同屏出现时，下方内容使用 `140ms` 延迟；在窄屏中下方内容较晚进入视口时，以其实际进入视口的时刻触发。
- 通过导航锚点直接跳转到目标区块时，观察器按目标内容进入视口的实际状态触发。
- 页面加载时已经位于触发区域内的标记元素，在观察器初始化后正常显示。

## 页面元素映射

| 页面区域 | 第一层 | 第二层 | 同组规则 |
| --- | --- | --- | --- |
| 粉色工作方向横条 | 横条整体 | 无 | 整体出现 |
| 三个分组 | 区块标题和介绍 | 三张分组卡片 | 三张同时出现 |
| 加入收获 | 左侧介绍 | 右侧收获列表 | 所有列表项同时出现 |
| 真实日常 | 区块标题和介绍 | 五张日常卡片 | 五张同时出现 |
| FAQ | 左侧介绍 | 右侧问题列表 | 所有问题同时出现 |
| 加入我们 | 左侧招新文字 | 右侧二维码卡片 | 二维码在第二层出现 |
| 页脚 | 页脚整体 | 无 | 整体出现 |

## 渐进增强与无障碍

- 默认保证正文可见；只有页面根节点同时具有 `reveal-ready` 状态时，尚未出现的标记元素才进入透明和下移状态。滚动观察器成功建立后才添加该状态，避免在脚本失效时留下空白页面。
- 如果浏览器不支持 `IntersectionObserver`，观察器将所有标记元素直接设为可见。
- 如果 `prefers-reduced-motion: reduce` 生效，所有标记元素直接显示，取消位移、动画时长和延迟。
- 动画不改变焦点顺序、语义结构、链接目标或可点击区域。
- 不使用滚动劫持，用户滚轮、触控滚动和键盘导航保持原生行为。

## 异常处理

- 单个元素缺少延迟配置时使用 `0ms`，不阻止其他元素显示。
- 观察器初始化或浏览器能力判断失败时，回退为全部直接可见。
- 组件卸载时执行 `disconnect()`，避免开发模式重复挂载造成重复回调。
- 动画状态只添加一次；已带 `is-revealed` 的元素不会重新进入观察流程。

## 验收与测试

### 自动检查

- 运行 ESLint，确认新增客户端代码和页面标记无静态错误。
- 运行项目构建和现有渲染 HTML 测试。
- 如现有测试无法覆盖客户端滚动行为，增加针对观察器状态变化与降级路径的最小测试。

### 浏览器检查

- 桌面宽度实际向下滚动，核对所有七个区域均出现。
- 手机宽度实际向下滚动，核对内容不会在进入视口前永久隐藏。
- 确认标题先出现，同组卡片或列表项同时出现。
- 向上、向下重复滚动，确认已出现内容不会重播。
- 使用导航直接跳转至“三个分组”、“加入收获”、“真实日常”和“加入我们”，确认目标区块正常触发。
- 展开和收起 FAQ，确认交互不受影响。
- 检查卡片悬停、图片缩放、按钮和二维码显示不受影响。
- 模拟 `prefers-reduced-motion: reduce`，确认所有内容直接可见。
- 检查浏览器控制台无新增错误，并比较动画前后页面布局，确认无明显布局偏移。

## 完成标准

- 所有确认区域都具有一致的 Apple 式平衡上浮淡入效果。
- 动画参数、出现顺序、同组同时出现和一次性触发规则与本规格一致。
- 页面内容与既有功能保持不变。
- 自动检查通过，桌面、手机和减少动态效果模式完成实际验证。
